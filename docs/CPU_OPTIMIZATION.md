# CPU 优化约束与当前结论 — 2026-11-03

用户已明确选择：尽量保持现有识别结果。

默认继续使用 SAM2 Large + TAPNext++、现有输入分辨率、CPU float32。不得因自动选择 CPU 而切换到 Tiny/NIU、降分辨率、跳帧或 BF16。小模型和混合精度目前均为隔离实验，不是已交付默认行为。

当前实测：
- 整段标准 CPU 1255.04 秒，GPU 179.03 秒。
- 减少 CPU 线程没有明显收益，保留本机默认 16 线程。
- BF16 的 SAM2 5 帧局部测试约 1.7 倍，但掩膜有变化，未进行整段验证，不默认启用。
- Tiny + NIU 完整视频为 396.33 秒，但有效姿态从 176/177 降到 160/177，不符合优先保持现有结果的目标。
- 另测 TAPNext CPU 注意力后端：原生 MHA 两次 4.793/4.391 秒；关闭原生 MHA 快速路径、交由通用路径选择 SDPA 后两次 4.146/4.110 秒。相同真实视频 5 帧、16 线程、float32，包含证据头采集。点位最大差异 0.000244 像素、可见性无变化。约 6%–10% 局部节省，不能视作全流程同等提速，更不能宣称逐帧完全一致。尚未启用为默认。

后续优化应先隔离测试，核对全部视频的掩膜、骨架、有效性、头尾和导出指标，再决定是否合入默认流程。原输出只作为一致性参照，不是人工准确率真值。当前没有证据支持在保留现有路线的条件下把 21 分钟大幅缩短为几分钟。

测试原始数据保存在工作区 delivery-validation/cpu-thread-probe、cpu-precision-probe、cpu-fast-candidate 和 cpu-attention-probe。
